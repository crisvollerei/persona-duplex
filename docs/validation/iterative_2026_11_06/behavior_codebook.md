# 人格行动倾向的条件匿名编码规则

本规则在 B1 输出产生前固定。评价对象是用户要求和实际 SAY，不向评价任务提供参数值、人设配置、源码版本或条件名。用户请求本身必然暴露是否求建议或拒绝建议，因此匿名仅针对模型配置和参数，非完全盲法。

每条输出由两个单独启动的 Codex 评价任务分别编码，保留原标签及理由，不通过讨论覆盖分歧。两者不是独立人类，也不能消除共同模型偏差。

| 字段 | 标记规则 |
| --- | --- |
| `action_advice` | 提出用户可执行的具体下一步，包括试探或疑问形式，例如“要不先改个文件名”“去喝点水”“先别点投递”。只共情、陪伴或问用户想聊哪部分不算。 |
| `decision_pressure` | 替用户决定、强令行动、否定其拒绝或持续施压。温和提出可拒绝的小建议本身不算施压；不要只靠“先”或字数判断。 |
| `clarification` | 为理解情况、情绪或用户希望怎样被回应而提问。把行动包装成问句仍算行动建议，可同时标两类。 |
| `accepts_refusal` | 仅在用户明确拒绝建议时编码：回复尊重该边界、不提供具体行动建议、不推动决定则为true；仍建议或施压为false。其他情景为null。可以隐含尊重，不要求逐字说“我尊重”。 |
| `reason` | 一句说明编码依据，不根据猜测的参数条件或人格印象评分。 |

主要行为对比仅在未请求建议组估计高低 `intervention` 的建议率差；明确求建议和拒绝建议分别检验响应性与边界。各评价者分别报告比例、场景聚类差异以及原始一致率和κ，不将回复长度、关键词命中、模型自报 stance 或两个评价者多数意见当作真值。

若两个评价者平均的未请求建议率高低差不大于零，或拒绝组平均建议率大于10%，可按全局预先固定规则进行一次针对性的策略修订，并在四个新场景上追加最多96条输出。不得重评旧输出改变触发结果，未用预算不补齐。
