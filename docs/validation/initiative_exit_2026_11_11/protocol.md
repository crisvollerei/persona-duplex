# 岚的主动性：收尾对照与跨会话影子检验

**短对照。** 用既有研究的岚、已独立选出的 examples 强提示、四个全新题材。每题只换最后一句，形成「替我选并解释」「只交付指定成品」「开放分享」。每条件、每路重采两次，48 个正式槽位。默认 text/full 通过当前 Session 实际交付；对照直接生成 SAY，共享人格资料、当轮文本与已确认状态，不提供答案或意图标签。冻结记忆，单次生成，无重试。温度 0.7，输出上限 900，两路相同。计划顺序使用固定种子打乱；无服务端共享种子。每一槽先登记再请求；若累计两次服务/传输失败即停止，空正文与协议异常单列。

**冻结判据。** 只在两类明确请求上诊断：委托题须有可辨认的选择及相关理由；成品题须交付指定内容且无新议程。前两题按用户要求逐字核对，后两题按实际使用能否整句复制判断，不按问号、句号数量猜测人格。对没有明确方向的分享不设“正确主动性”。用去方法标记的乱序文本编码，保留每条理由；无法判断则保留不确定。就同一类问题，只有当前框架在两个题材各出现至少一次明确失误，或在同一题材两次均失误，才进入局部修改；服务错误不算人格失误。若触发，编辑只改变对应条件，并在新材料上与未改框架和同信息强提示确认；若不触发，不改默认实现。任何开放情境的真人偏好结论都需要独立真人评分，模型或机械检查不可代填。

**跨会话检验。** 独立于短题结论，先使用可公开的合成关系史，经多个 Session、关闭和重开，再从同一历史快照分叉。区分三层：（1）完整账本记住了什么；（2）最近历史和召回实际把什么送进请求；（3）两种方法最后交付了什么。明确记录由应用写入并有原话，更正与过期版本不得冒充有效事实。两路收到同一份从快照取出的近期可见对话与召回资料；不因一边答错就单独为它补历史。使用稀疏的人格偏好、项目事实和未确认约定作为探针，不公开任何私人会话。这个阶段不测自动提炼准确率，不声称等价于实际生产流量或用户体验。
