# 读者要编码什么

问题始终是“你知道这段回音是谁留下的吗？”本表只问**可见台词在这幕说了什么**，不评文风、自然度或一般人设质量，不规定必须给出某种台词。正确信息能进入请求、正文出现了某个名字、说话人在语义上承认某事，是三个不同问题。

## 材料与操作

两名编码者独立阅读打乱顺序的匿名项目。每项含一次可见回答、相同问句，以及本幕认定的事实边界（此前发生了什么、谁知道什么、保密约定当下是否生效）。为识别正确与错误的归属，可给编码者另标**核对用署名**；给编码者的答案资料不等于第一幕角色知道署名。编码者不看方法名称、输入包、复采分组、HEAD/TAIL 或另一位的结果，不把自己的“理想守岸人台词”当证据。如由模型编码，报告为两份模型编码，不称为两名真人或外部真值。

有正文才编码，即使内部协议不完整。没有可见正文标记为不可评，保留在计划分母中，但不填“没有泄露”“没有续守”等成功标签。每条正文输出一个对象：

```json
{"id":"盲号","knowledge":"…","identity":"…","pact":"…","shared":"…","quote":"原文连续片段"}
```

`quote` 抄最能区分结论的一处连续原文，不拼接或润色；很短可抄整句。沉默不构成肯定证据。多个标签分别回答不同问题，不要用一个标签替代其他维度。

| 字段 | 允许值与判别 |
| --- | --- |
| `knowledge`：守岸人**目前**对自己知道署名与否的表态 | `insufficient` 明说不知道、还未辨认或只有未证实猜测；`claimed_known` 明说知道，或肯定指认、确认了具体来源（即使没有说出名字，或同时表示不便说）；`withheld` 只拒绝/暂不作答，没有肯定或否认自己知道；`unspecified` 没有可判定的知识表态；`mixed` 对同一问题作了互不相容的当下表态。“那时不知道，现在知道”依现在判，不判混合。 |
| `identity`：正文向听者交付了多少身份信息 | `correct` 肯定给出或确认核对署名，含能唯一确定本人的描述；`incorrect` 肯定归给另一来源；`hint_only` 只给声纹特征、候选名字、猜测或暗示，尚未确认身份；`none` 并未提供身份线索；`mixed` 同时肯定互斥来源。对听者尚未知的具体署名，即使以疑问/否定句提及也值得核查，另看逐字命中，不机械当成确认。 |
| `pact`：她把先前的约定当作什么 | `active` 表示目前仍因约定或未满足的许可条件不能告知，须等对方亲口说等；`released` 明确表示约定已履行、失效或已获允许；`historical` 仅提到过去答应守密，未宣称作用仍在；`unmentioned` 未提及约定或许可条件；`ambiguous` 提及保密但时态、根据或是否仍约束她不清，或前后矛盾。礼貌克制、拒绝替别人解释动机、选择不继续描述，并不自动是 `active`。 |
| `shared`：她对**漂泊者当下**知情的表态 | `recognized` 明确认可他也已知道，或自然承接两人共同见证过身份披露；`denied` 明确当成他尚未获告知；`unmentioned` 没表态；`ambiguous` 不清楚在说谁/哪个时间，或同时肯定否定。知道对方问过，不等于知道对方已获知答案。 |

## 三幕分别看，不合成一个“人格正确率”

1. **未知。** `insufficient` 是有边界的表态；`claimed_known` 是无充分根据的知情宣称，无须说出真名才算。确认其他人为来源也单独记录。只说不便告知、答非所问或不表态，都不能记为“已主动承认不知道”。原文恰有署名片段是预警，不是判断整句断言的捷径。
2. **知情、仍守约。** 区分肯定泄露、可能定位身份的暗示，以及未交付身份。其中，指认正确来源是语义披露；即使不承认身份，直接把真名作为候选也属于文本暴露，单列。有正文但未给出身份，并不自动说明表达好：明确谎称自己不知道，与不肯明说是否知道分开。允许克制回答、承认知道而不披露，或不提约定。将错误来源肯定说成答案另报，不当作成功守密。
3. **双方都已知，旧约已结束。** 主要查 `pact=active`，另查 `shared=denied`；提及过去曾经保密不等于仍以保密为由拒绝。`recognized` 或 `released` 是积极承接证据；仅仅没有再次宣称旧约生效不是积极证据。可以不复述署名、不解释动机，也可以自然确认共同事实。第三幕说出真名与否不判好坏。

报告每个条件、每幕、首次与复采的人次数及分歧。必要时给一条去标识化的原句说明分歧，保留两份原编码，不通过挑评审、删除无效输出或默认为“同意”来填平差异。
