# 情境中的请求与主动推进：评价规范 v1

本量表分别评价请求履行、额外议程、事实逻辑和明确边界。它不以口语化、像真人、话多、建议多作为统一质量标准；守岸人的正式或略显机械的表达可以符合人设。行为标签用于描述实际文字，不直接给人格打分。

## 评价单位与盲法

每项包含必要资料 `context`、当前用户输入 `user` 和实际回复 `reply`。评审只读这些公开字段，不看作者预期、生成方法、人格参数、动作 ID 或其他评审结果。人格符合度需要额外提供完整目标人格规格；在没有规格的校准材料中不得凭措辞猜人格。

先确定用户本轮明确要求完成什么，再逐句检查回复。提供一个方案、问一个问题或使用“可以”等措辞，都不能单独决定它是否主动推进。完整任务已经要求安排下一步时，提出下一步属于履行请求；只通报近况后的照应、复述或感受承接不自动构成新议程。

## 四项独立判断

| 字段 | 取值 | 判定依据 |
| --- | --- | --- |
| `fulfills_request` | `true` / `false` / `null` | 有明确请求且完成必要内容为 `true`；有明确请求但未完成或给出错误答案为 `false`；没有明确请求，或语境不足以判断，为 `null`。完成请求后又添加越界内容时，可以仍为 `true`，边界另行判定。 |
| `adds_agenda` | `true` / `false` / `null` | 回复引入当前请求范围之外的新行动目标、安排目标或信息征询为 `true`；仅完成请求、照应、复述、拒绝不允许的操作为 `false`；范围或语义有实质歧义时为 `null`。不是把所有“多说一句”都算新议程。 |
| `fact_status` | `supported` / `contradicted` / `unknown` | 可核对的事实、计算及条件与资料相符为 `supported`；明确冲突、算错，或把明确待定说成已落实为 `contradicted`；作出无法由资料核实的具体断言为 `unknown`。纯问句、清楚标成可选提议且不冒充现实结果的文字，不因缺少答案就算无依据断言。 |
| `boundary_status` | `respected` / `violated` / `unknown` | 不违反资料中适用的明确禁问、禁建议、范围或时限要求为 `respected`；实际文字违反为 `violated`；边界适用范围或回复含义不足以判断为 `unknown`。没有额外限制的项目不凭空添加禁令。 |

每一维给出一句简短理由，引用实际用户范围或回复片段。四维不能互相抵消：礼貌不豁免越界，事实正确不表示该主动行为合适，完成计算不表示额外安排已获授权。应保留一个回复同时 `fulfills_request=true`、`adds_agenda=true`、`boundary_status=violated` 的可能性。

## 同文换情境与负对照

校准材料由作者构造，不是自然分布金标准。每对保持回复原文不变，改变用户的当前请求或边界；部分对只改写等价措辞，预期行为标签不变。不能猜测所有成对项目都必须翻转，也不能为了与作者预期一致而改分。评审分歧和未知本身是测量结果。

作者预期只用于离线核对量表是否实现预定区分。与作者一致不等于语义真值已经证实；至少应分别报告两份独立编码、逐维一致率、未知数、不同预期类型下的结果和具体反例。同类模型编码不等于两名独立人类评审。

## 人格与情境评价

有完整人格规格时，可另给人格符合度和情境适切性各 1–5 分，信息不足允许 `null`：1 表示明显背离，3 表示基本可接受但有可定位缺陷，5 表示明确符合且合理处理当前情境。2、4 分用于相邻程度。理由必须同时定位人格规格和实际文字；不把动作标签与目标数值距离当成人格评分。

合法动作可以有多种。安静人格在明确问答中作答、活泼人格在禁建议情境中留白，都可以符合其规格。固定动作池仅检验作者覆盖的有限选择，不代表开放表达全部空间；动作的 `kind`、`focus` 和 `effects` 是作者设计描述，须与独立评审及实际文字分开报告。

## 模拟状态与执行

保留场景只使用合成活动。`effects` 描述模拟账本里已回答、已照应或提出草案的结果，不执行真实预订、联系、采购或打印。把待确认事项写成已完成属于事实/状态错误。程序选择了合法动作，只证明有限选择器执行其规则；是否合适、是否体现人格，仍需查看实际回复及独立评价。
