# 端到端记忆补充实验方案

本实验是在主实验完成后追加的探索性补充，方案在补充请求开始前固定。它保留主实验的协议与数据，用真实会话生成、真实缓冲、真实模型固化和新会话探针补充主实验的人工记忆注入对照。机器可读方案见 [supplement_protocol.json](./supplement_protocol.json)。

固定四次独立重复。每次建立独立 Store，依次输入三条用户明确陈述的个人习惯：专注 17 分钟，休息 3 分钟。三个用户输入均重复该习惯；前台回复使用主脚本的中性配置、默认 text 协议与相同模型参数。完成后手动调用一次 `Consolidator.run_once()`，通过 `text_prompt(Recorder("text"))` 实际请求模型提炼判断与陪伴记录。此处测试固化机制，不测试 300 秒定时调度。

固化所得判断原样保存，并与本重复的训练 turn_id 对照。载入组的新 Store 只导入本次实际生成的判断；空白组的新 Store 不导入判断。两者历史均为空，使用相同且不含 17 或 3 的探针，请求输出之前明确说过的专注与休息时长，没有依据则答未知。两种探针次序使用主实验种子固定随机化，每组每重复仅生成一次。训练、固化、探针的所有原始调用均另存，不重试失败样本。

主要描述性指标为两项时长都正确的重复数，分母固定为每条件四次。额外报告空白组未知率、协议有效性、流式一致性、固化判断及其证据范围、未消费缓冲、参数前后是否相同。固化前后各参数都应相同，程序不调用成长接口。载入组不能获得人工补写的目标记忆，固化未产出判断也不人为补全。

另保存训练 Store 的判断和参数，清空该实验自己创建的两种派生视图，调用 `rebuild_views()` 后记录字段级相等结果及重新生成的视图内容。原始账本保留。这个检查仅评估本次已入账数据的重建，不等于跨进程或任意磁盘损坏的恢复保证。

四次重复总计计划 12 条训练回复与 8 条新会话探针，共 20 条对话输出；固化调用另计。补充实验发生于同一运行时段，不称为隔日召回。小样本结果不用于宣称普遍记忆可靠性或单独的因果确认。输出分别为 `supplement_results.json` 和 `supplement_raw_calls.json.gz`。

运行：在进程环境设置 `PERSONA_API_KEY` 后执行 `python -B -X utf8 docs/validation/followup_2026_11_05/supplement_memory.py --run`。无 `--run` 时仅显示计划；`--self-check` 仅运行不联网的评分、固化与重建检查。
