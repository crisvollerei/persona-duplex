# 强传统提示与框架的共享资料对照方案

研究日期：2026-11-07。全局方案、任务、金标、语料、实际共享资料、提示模板、实现快照及评价规则在首个在线请求前固定。仓库内前置固定不是第三方注册平台的预注册。

## 目标

比较两种完整提示组织在相同来源资料和表达配置下的目标保持、必要条件、无依据断言、人格表达及实际成本。不预设框架占优；没有差异、天花板或框架退步均保留。工程状态管理、检索算法质量、长上下文能力与判断硬隔离不属于本实验识别目标。

## 因子与规模

主试验为两方法（传统强提示、现行默认text框架）×三表达配置（中性、蓝鱼、白龙）×八任务族×两个固定实例×两次独立新会话，共192次。八族是迎合错误计算、证据不足仍要求确定、必要条件、时间更新、对象区别、临时例外、未解决冲突、检索引文中的伪指令。

另有四个开放交流问题×两方法×两人设×两次新会话，共32次。总224个单元、224条计划输出、224次计划请求，硬上限256；不按结果扩样、不替换失败、不自动重试。三次请求/生成错误后拒绝新请求，已在途请求可结束。

中性配置清空身份，将九参数设为0.5，仍是操作化的表达参照，不是没有人格因素或独立中性推理的神经参照。每种方法都有自己的中性条件，避免把方法本身的差异归为人格配置效应。

## 传统基线与信息公平

传统提示不是一句简单人设：它接收相同identity、voice、注意倾向、参数端点语义、适用例句、事实与表达分工、未知处理、接受否认及尊重拒绝等要求；只输出实际回复。框架保留其完整三段协议。两者是完整提示包对照，不能从差异识别单个组件的因果贡献。

冻结语料共120份。每题按不带任务含义的实体编号过滤，得到该实体全部六份原始资料，再用固定词法分数排序。因为top-k等于该实体文档数，排序只改变次序，不做语义挑选。每包最多2600个Unicode字符，完整保留文档，不填满上下文。

模型可见字段只有不带语义的来源ID、主语、日期和原文。研究内部的family、诊断type和金标不进入模型输入。实际资料包以逐字相同的system尾部数据块提供给所有方法、配置和重复，核对内容哈希；共同规则也相同。框架长期记忆冻结为空，不把资料改成带额外置信度的已接受判断，不运行后台固化。该设计控制证据输入，不评估检索召回质量或RAG压缩优势。

两方法同模型标识、温度、单次调用和输出上限；实际token、响应时延和异常分别报告。相同调用数不等于相同计算成本，不给传统方案填充无意义文本追平成本。

## 评价

固定自动提取器单列覆盖、覆盖内正确、已分配试次的可提取成功、结论标签和联合严格结果。未提取的 `target_correct` 是null，不直接当事实错；允许预先列出的空白、数值格式、单层外引号和标签等价形式。必要条件词面命中仅作观察，不作为语义保留真值。

两套方法匿名Codex任务评价全部实际回复的所问结论（correct/incorrect/no_answer/ambiguous）、无依据断言、必要条件和用户边界。另对两人设作1—5角色一致性、自然度和配对偏好评价；中性角色一致性为null。评价者可见表达参考，无法对人设本身匿名；只隐藏方法、参数标签、原始模型元数据和自动分数。两套标签不合并为真值，不声称独立人类评价、人格质量非劣或普遍体验优势。

112组左右配对在输出产生前按固定种子平衡，传统/框架各56组位于A侧。评价输入去重共同资料，避免重复来源膨胀；缺失输出不伪造，完整配对覆盖单列。详见[评价规则](review_codebook.md)、[前置评价方案](review_protocol.json)及[固定配对](pair_assignment.json)。

各方法相对自身中性参照的配置效应和方法交互按任务族聚类配对bootstrap4000次，分别保留蓝鱼/白龙，不将所有相关重复当独立样本。八个主任务族与四个开放问题范围有限；逐输出Wilson区间仅作描述，不进行确认性显著、等效性或硬隔离证明。

## 运行与材料

请求模型deepseek-chat，温度0.7，最大输出2000 tokens，超时120秒，四线程。保存实际返回模型标识、响应元数据和服务返回用量，未知不填零。本地随机种子不是服务端采样seed。

保留计划、实际输入、原始增量、SAY、来源包哈希、源码及配置哈希、异常、两套标签、离线分析和绘图。API认证仅放进进程环境，不写入材料；语料为合成数据。此研究不更改现有框架源码或旧实验结果。
