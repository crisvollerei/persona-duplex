# 两份独立编码的共同操作说明

只阅读本文件、rubric.md、reviews/inputs.json及自己正在写的评分文件。不要打开其他材料、来源映射、代码、校准答案、另一位编码者结果，不调用API或外部资料。以输入中提供的适配人格为准，不凭外部角色印象覆盖它。

按rubric给每项独立评分并保存JSON数组至分配的ratings文件。不要以通用自然度给正式或机械表达扣分；也不能为了“符合人格”忽略事实、必要任务和明确边界。每项各维度都有独立含义，分歧和未知是允许的。

共同术语澄清：grounding中的“角色约定”指已许可的虚构背景、角色语言与现实事实界限，不包含所有行为价值规范。违反人物“尊重选择”等价值可以影响persona_fit或boundary，但不因此自动变成事实错误；若同时存在事实断言错误，应分别说明。真正有歧义的说法可标uncertain。不要以“可能存在某种读法”强迫支持或违反。

引用必须逐字来自本项。say_quote可用完整回复；context_quote来自用户原话或历史（允许空字符串）；persona_rule来自本项spec的逐字规则。reason用简洁中文说明人格、情境、事实与边界及行为判断的重要依据，违规时必须指出问题。格式检查只检查schema、引用和ID，不因预期结果修改标签。

不同项可能文字相同而人格不同，仍需按各自规格评价。不能为了制造人格差异强制给不同分数。不得猜测哪些是校准项，也不依据任何假定的实验假设调分。
