## 证据结算与关系观察

需求读法是生成回复的参考，不要求每轮记录预测或立即结算。

| 情况 | 处理 |
|---|---|
| 明确提供所预测的内容 | 可记录 `CONFIRMED`，附证据 |
| 明确反驳所预测的内容 | 可记录 `REFUTED`，附证据 |
| 仅同话题、换题、连续短回复或时间经过 | 保持 `WATCH` |
| 超过保留期 | `EXPIRED`，没有对错结论 |
| 语域突变 | 独立记录暂定的疑似受伤信号，不覆盖预测真假 |

可选语义判定器异步运行；失败或超时时，字面兜底只观察相关性，不据此判对错。
模型 TAIL 的 confirmed/refuted 必须提供非空证据。队列总量默认最多 8 条，保留期默认
72 小时。关系增量使用白名单和单轮限幅。

语域信号只打开暂定修复，不借用预测置信度来证明受伤。短回复、换题或语气放松不代表
修复成功；明确要求停止时暂停，连续两次尝试仍无明确反馈也暂停，不自动新增长期雷区。
修复状态描述的是系统尝试与用户内容，不是对用户心理的诊断。

完成且通过本地协议校验的轮次写入记忆缓冲；后台线程默认每 300 秒尝试固化，提炼关于用户的可推翻判断，
并记录角色的陪伴经历，不阻塞每轮回复等待提炼。自我叙事中的“我”指角色，
不将用户经历当成角色自身的经历。默认后台不自动调整 `bias`、`traits.value` 或
`traits.anchor`；参数更新、`push_traits()` 和 `push_anchors()` 供显式实验调用。

记忆缓冲由本地提交发布；同一 Store 的定时、手动和退出固化串行消费，
但不占用前台读写锁等待模型。普通新增判断与对应陪伴记录生成完成后原子提交；纯更正或撤销批次不额外生成陪伴叙事。失败则保留积压，
等待后续固化处理。
配置了记忆模型时，请求或 JSON 解析失败默认不切换计数策略；无模型路径仍使用明确标记的
启发式计数，只记录模型怎样重复解读，不据此生成用户倾向或提高判断置信度。
这些诊断记录留在账本供分析，不进入前台用户记忆、冻结快照或后续提炼的已有用户判断，
也不会挤占用户判断的数量上限。旧版带计数来源标记的记录同样排除，不删除历史。
指标与校准报告将“读法诊断”单列，不把计数记录算作用户判断产出。
模型提炼明确区分用户原话与模型的 need、direct、SAY；重复的模型解释不算重复的用户证据。

### 内容等价、有效版本与相关召回

记忆判重使用独立的保守文本等价规则，不复用话题相似度。仅规范有限排版差异；数字、英文名称、单位、否定、条件及有意义的标点变化不自动合并。普通候选中的不同内容保留为独立暂定判断，不擅自生成更正操作，也不会把新值的来源附到旧正文。只有来源和目标均通过检查的显式更正或撤销，才使旧版本失效。

模型普通候选没有来源时仍可留在账本，但标记为`unsupported`，不进入默认用户记忆或陪伴叙事；不为它补造来源。应用显式写入及旧版未标来源的迁移记录保留兼容，不因此获得事实认证。

默认前台从全部有效用户记忆中，按当前问题做本地词面召回，保留数字及英文名称；默认最多5条，完整记录的JSON字符预算为6000。超预算记录整条跳过，不截断原话、否定或条件。相关性只决定候选，不证明记忆内容正确；未解决冲突保持未知。`Store.user_judgments()`仍是近期视图，按问题读取使用`Store.recall_judgments(query)`。每轮`memory_recall`记录实际选入的ID、范围与预算，不增加模型调用。

应用可显式设置`memory_scope`、`valid_from`、`expires_at`。检索先排除已替换、撤销、过期、未到起始时间及不适用范围的记录，再排序；时间必须带时区，不从自然语言自动猜窗口。范围是同一用户数据目录内的应用过滤，不是跨用户访问控制。模型在局部范围内不能更正或撤销全局背景；跨范围操作由应用显式确认。

每轮记忆积压保存应用指定的作用域，后台只消费当前作用域的积压。切换作用域不会给旧积压重新归类；旧版无标记积压视为全局。其他作用域的积压继续保留，应使用相应作用域的会话固化。

更正继承原记录的范围与时间窗口，不允许用`supersedes`同时改变它们。临时例外应另存独立记录，保留基础设置；例外到期后仍可召回基础设置。固化器按本批用户文字检索最多40个相关历史目标、24000字符，不只看最近40条；新来源仍只能来自当前处理批次。

冻结模式保存会话开始时的完整有效候选集合，每次仍按当前问题及应用条件本地检索，不读取之后新增的live记忆。默认仍为追加账本和全量视图扫描；本地检索不等于已解决任意历史规模的性能或语义理解问题。
已接受的模型判断同时保留对应 `evidence_ids` 的完整用户原话，引用会核验来源，
避免具体数字、单位、名称、否认或更正被抽象描述吞掉。重复判断只追加新的来源引用，
不因此提高把握度、生成新倾向或推动人格参数。前台优先读取较新的完整引用，
当前明确更正优先；批次引用只作背景，缺失或冲突的细节保持未知。
库接口 `Consolidator(heuristic_fallback=True)` 可显式允许模型失败后退回诊断计数。
判断记录区分 `llm / heuristic / heuristic_fallback`，并保存批次及证据轮次；未指定细粒度
证据时标记为批次范围，不伪装成逐条证据匹配。

重启后下一次固化会恢复 `buffer/processing/` 中的暂存事件，并跳过已提交消费的事件。
坏缓冲文件保留为 `.invalid` 并记录错误。这仍是单进程文件存储，不提供跨进程事务、
多进程同时打开同一目录或任意断电/磁盘损坏下的恰好一次保证。

三层状态的职责：

| 时间尺度 | 状态与职责 | 当前边界 |
|---|---|---|
| 短期 | 本轮读法、pending、关系与语域基线 | 在线受限写入；内部参考不是人格的真实内心 |
| 中期 | 可推翻的用户判断、经历对当前参数的影响 | 记忆提炼已接入；参数推动仅供显式实验 |
| 长期 | 角色的陪伴叙事、人格基线的缓慢变化 | 叙事已接入；基线推动仅供显式实验，需附依据 |

稳定基线是观察位移的参照，不等于人格必须永远冻结。经历如何可靠地推动参数仍待设计和验证；
不能把用户的性格、某个 need 的出现次数或预测命中率直接等同于角色成长。

## 个人偏好与约定的更正、撤销

模型把握度与用户更改自身偏好的效力分开处理。`Store.apply_memory_operation()` 接受
`revise` 或 `retract` 提案：前者产生替代判断，后者只使旧记录失效，不编造新的偏好。
该接口只处理 `user_preference` / `user_agreement` 范围；用户自述不因此成为外部事实。

操作须明确给出活跃的 `target_id`、`basis="explicit_user_statement"`、本批 `evidence_ids`、
来自实际原话的 `statement` 及关联主题 `target_anchor`。目标原话必须能回查更早的真实用户轮次，
当前完整引用须对应已入账轮次或固化器选定的用户事件。主题或来源关联不清楚时拒绝变更并记录原因，
不按新旧 confidence 大小决定合法更正，也不提高判断置信度。

模型可在原有提炼调用内提出操作，无需额外模型裁判。已有判断的历史引用与本批可引用ID明确区分；
不存在或不属于本批的ID仍被拒绝。模型返回的完整字符串或足够长的定位片段，只有在已指定来源中
唯一逐字匹配时才可规范化；程序始终取回完整原话，保留否定、引用和临时条件。定位片段本身不作为截短后的证据。

`memory_quote_normalization` 记录定位与原文，`judgment_operation` 记录提议、生效状态、拒绝原因、
原主题与主题核。`run_once()` 返回 `memory_operations` 和 `quote_normalizations`。
主题核只按固定规则剥离泛化修饰词，仍须在两侧原话中出现，不作近义或模糊匹配。
这些是来源完整性与词面操作边界，`semantic_status="model_proposal"` 不代表模型已正确理解语义。

公开的旧 `add_judgment(..., supersedes=...)` 调用保留历史行为；固化模型的旧 `supersedes` 提案
也须通过来源操作校验，不得借兼容字段绕过门控。操作及撤销结果随账本重放和视图重建保留。

## 账本、运行记录与报告

```text
data/<会话目录>/
  ledger.jsonl      追加式事件与本地提交封套
  state/            物化视图
  judgments.jsonl   旧版判断文件；仅兼容导入，新判断以账本为准
  self-story.md     角色的陪伴记录
  buffer/           尚未固化的事件
```

`Store.read_ledger()` 仍返回展开后的事件列表；直接读取 JSONL 的外部脚本需要识别
`kind: commit` 封套的 `events`。短事务先将事件、视图快照与待发布缓冲写入同一个追加记录，
再发布视图和缓冲；重启根据提交检查点补完发布。截断的坏尾行保留，但不再吞掉下一条记录。
状态重建优先使用实际提交快照及随事件记录的限额，不用当前默认值改写历史结果。

每次运行保存完整配置、配置哈希、运行源码哈希、协议、条件标签及适配器可知的模型/采样设置；
每轮关联实际输入状态、模型请求、输出和可获得的响应元数据。API key 不写入模型元数据，
端点中的认证信息与查询参数也会剥离。自定义调用器或未记录的扩展条件明确标记为未知，
不能据此保证第三方模型完全复现。

会话保存最近 12 条对话消息、独立判断历史、20 条话题窗口及必要运行状态，
可恢复接续，不是把整段历史永久塞回提示词。叙事记录和基线推动频率也有账本依据。
历史数据缺失的字段保持未知；没有入账的独立叙事文件在重建时保留。
`persona` 实验的 turn 另记基础判断约束、额外开关及已执行的模型检查结果；失败记为 `generation_failure`，
包含失败阶段、内部判断、候选与已交付片段，不伪装成完整交付，也不据残句生成新的观察假设。

| 命令 | 用途 |
|---|---|
| `stats` | 位移、预测校准、声明检测、修复和参数状态统计 |
| `calibrate` | 观测分布、判定覆盖和耗时诊断 |
| `lift` | 按 claim 原文首见/重复分组的命中率差值 |
| `rebuild` | 按账本恢复已记录的状态 |

位移率只计通过本地协议校验、且有明确人格基准及对应口径的记录。缺字段、无效枚举、
不合法置信度、流式中断与被拦截的输出单列，不当作正常“无位移”样本。
这里的有效仅表示本地协议有效，不证明事实正确、语义位移或人格效果成立。
`lift` 是描述性统计，
不是有/无记忆的因果实验。`rebuild` 不按新参数重跑模型，也不重新判定旧事件。
模型判定和修复状态不是独立真值，命中率不等于用户认可度。

账本含用户原文、内部参考和完整请求内容，是敏感实验数据，不应直接公开或提交到仓库。

完整命令示例见 [使用说明](how-to-start.md)。
