# 人格与生成协议

[文档导航](README.md) · [项目首页](../README.md)

内置 `default`、`service`、`guarded`、`shorekeeper`、`ache` 五套 TOML 配置。
人格由身份文本、语感例句、注意力、站位和行为参数共同描述：

- `bias`：把握度偏移，影响站位选择。
- `attention`：只读表层或同时考虑潜台词。
- `legibility_max`：相对人格基准的表达策略；0 不作额外位移，1 限于轻微局部变化，
  2 允许更明显的转移与保留。1/2 使用不同提示约束，不是已测量的语义幅度上限。
- `traits`：行为参数，包含 `anchor / value / plasticity / drift / lo / hi`。
  提示词包含当前数值和两端语义。

五种句式场景都有入口：首轮使用 greeting，comfort 在默认单次生成中参考上一轮 need，
promise / answer / farewell 根据本轮用户文本的明确关键词触发。它们是确定性的参考选择，
不是完整的语义分类器。`special` 必须配置非空 `keywords` 数组，匹配当前文本才注入；
`when` 只作说明，不能指望程序自行理解任意自然语言条件。
配置在调用前检查数值范围、参数名、站位区间、限额和触发词，错误配置直接报错。

| 协议 | 正常调用数 | 分工 |
|---|---:|---|
| `text`（默认） | 1 | 一次生成 HEAD（含 direct）、SAY、TAIL（含 pending） |
| `persona` | 3 | 显式实验：独立基础判断、人格层 HEAD + SAY、观察 |
| `tool` | 3 | 显式实验：带人设的内部参考工具、SAY、观察工具 |
| `auto` | 按路径 | 显式兜底：文本协议连续失效时切换到 tool，不提供判断隔离 |

`persona` 只有显式指定 `--protocol persona` 时才启用，记忆仍在后台异步提炼。
它的基础判断提示和 schema 不读取人格配置，包括需求分类词表，并另列事实边界 `constraints`。
基础判断历史只使用独立步骤的结果，不把单次生成协议中的 `direct` 当成中性结果。
实际对话会作为引用数据供理解指代与问答，不转发历史 HEAD/TAIL；角色台词不作为现实证据。
这避免了只保留素回答时误解「是」「还没」等回应，但历史口吻与用户原话仍可能间接影响结果，
不保证完全中性。会话保存最近的基础判断与表达历史，重启可接续；
旧数据缺失的历史不从单次生成的 direct 推造。

CLI 的 `text` 默认路径不创建或调用结构化工具。
显式选择 `persona` 后，CLI 使用结构化工具；工具失败默认报错，不自动换格式重试。
该协议的库调用未配置 `tool_llm` 时，直接选择 JSON 文本作为正常传输方式，不先尝试工具。
两种传输均校验关键字段，不改变分层输入边界。

`persona` 另有默认关闭的 `--check-fidelity`（额外事实一致性检查）和 `--json-fallback`
（工具失败后同阶段换格式）实验开关。它们不是人格机制成立的前提，也不参与默认主链路。
检查不是要求 SAY 复述全部内部判断，也不是人格效果或事实正确性的证明。
库接口与开关细节见 [使用说明](how-to-start.md)。
`--no-judge` 只控制话题判定与模型记忆提炼，不控制上述可选开关。
调用数不含显式开启的审查、格式回退、异步话题判定或后台固化。

```powershell
python -X utf8 -m persona chat -p shorekeeper --protocol persona -m deepseek-chat -d data/sk-persona
```

默认文本协议结构（以下三段是同一次调用的输出）：

```text
<<<HEAD>>>
need: 暂定的需求读法
confidence: 对读法的把握度
direct: 中性的素回答
baseline: 当前人格通常会怎样回应
displace: 相对 baseline 的额外位移；none 是常态
<<<SAY>>>
实际说出口的话
<<<TAIL>>>
settle: 有证据才结算，否则 - 或 watch
pending: 可选的后续观察假设
delta: 受限的关系增量
```

站位依据本轮 `HEAD.confidence` 和配置表选择，不借用上一轮的把握度来约束当前回答。
它只约束对需求、潜台词的人际表达，不压低已知事实或计算结论的确定性。
流式中断后仅记录已经交付的 SAY，不重试、不提交未完成的 TAIL，也不将残句送入记忆提炼。
可疑内部标记和脚手架在逐片输出时拦截，而不是等全部输出后才清洗。
